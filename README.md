# Hulton Hotels

Spring Boot web app for hotel reservations and reviews, backed by MySQL.

## Running

Requires Java 21+ and Docker.

```sh
./mvnw spring-boot:run
```

Spring Boot's Docker Compose support starts the `mysql` and `minio` services from `docker-compose.yml`
automatically. On startup Flyway creates the tables and loads sample data (see
[Database](#database)). Then open http://localhost:8080.

To run the app in Docker too (only Docker needed), start the `app` profile. It runs
`mvn spring-boot:run` on your checkout in a Maven container; the first start downloads
dependencies and takes a few minutes. Set `APP_PORT` to use a port other than 8080.

```sh
docker compose --profile app up
```

To run against another MySQL instead, set `DB_URL`, `DB_USERNAME` and `DB_PASSWORD`
(see `src/main/resources/application.properties`) and pass
`-Dspring-boot.run.arguments=--spring.docker.compose.enabled=false`.

## Frontend

Pages are Thymeleaf templates (`src/main/resources/templates`) styled with Tailwind CSS v4.
The stylesheet is built from `src/main/frontend/app.css` into `static/css/app.css` during the
Maven build, using a project-local Node that Maven downloads into `node/` — no global Node needed.

While editing templates, rebuild the CSS on every change with:

```sh
node/node node/node_modules/npm/bin/npm-cli.js run watch:css
```

(or `npm run watch:css` if Node is installed). If you run the app from the IDE, run
`./mvnw generate-resources` once first so `app.css` exists.

## Database

Flyway migrations run on startup:

- `src/main/resources/db/migration` — the schema (`V1__schema.sql`). Add schema changes here
  as `V2__…`, `V3__…`.
- `src/main/resources/db/sample` — demo data: four hotels with breakfasts and services
  (`V1_1`), 24 rooms per hotel generated by `src/main/java/db/sample/V1_2__Sample_rooms.java`,
  and guests with past and upcoming stays, reviews and room discounts (`V1_3`).

Sample guests sign in with the password `password`: `maria@example.com`, `james@example.com`,
`priya@example.com`, `daniel@example.com` and `sophie@example.com`.

## Photos

Hotel and room photos are stored in MinIO (the `minio` service), in the private
`hulton-images` bucket, and served by the app at `/images/<key>`. The `hotel.ImageKey` and
`room.ImageKey` columns hold each photo's object key, e.g. `rooms/suite.jpg`.

On startup the app creates the bucket and uploads the sample photos from
`src/main/resources/sample-images` that aren't there yet (turn off with
`hulton.images.seed-samples=false`). Browse the bucket in the MinIO console at
http://localhost:9001 (user `hulton`, password `hulton-secret`). Photo credits are in
`sample-images/CREDITS.md`.

To skip the sample data, set `spring.flyway.locations=classpath:db/migration`. To start over
with a fresh database: `docker compose down -v`.

## Tests

```sh
./mvnw test     # unit tests: JUnit 6 + Mockito, and @WebMvcTest controller tests (no database)
./mvnw verify   # also the *IT integration tests, against MySQL 8.4 in Testcontainers
```

Integration tests need Docker. They start their own throwaway MySQL (see
`src/test/java/com/hulton/hotels/support/TestcontainersConfiguration.java`), run the Flyway
migrations and sample data in it, and roll back after each test, so they never touch the
database from `docker-compose.yml`.
